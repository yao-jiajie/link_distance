# 修正版 boundary X-sweep：原型结果

本文保留首轮 X-only 实验原始结论与数值；其中“尚未实现 Y/Z/best-axis”仅指该历史版本。
当前代码已补齐三轴与 best-axis，见 [最新五组结果](octree_boundary_xyz_results.md)。
`benchmark_boundary_tree.py` 当前默认执行五组对照，不再仅运行本页的两组矩阵。

本轮完成了有上限的 X 扫描原型，默认 AABB 路径保留。结果不是全面替代 rect：
相机/U 样例树和查询有收益，椭球样例反而更差，完整验证开销仍然很大。

## 关键语义修正

新树表示 `closure(R³\V)`，不是严格补集。严格查询通过 `boundaryStrictFree()`：
树值小于零返回自由，大于零返回占据，零值查同一帧原始闭占据 Octree。
这既排除原始占据体素边界，又保留自由盒子的内部接缝。没有改动共享树的 `<=0` 语义。
`strict_free_space.json` 是消费者入口，不能单独把闭包树的 `<=0` 结果当作严格自由。
这里的“自由”仅相对观测体素，不代表机器人已确认安全的空间。

## 实验设置

2026-09-08，本机 Release，CGAL 5.6.3。h=0.04 m；每配置预热 1 次、正式测量 5 次，
volume/boundary 交替顺序、串行执行。输入与二进制哈希、每次命令和原始时间均保留。
只有模拟/合成数据，无真实扫描，无 CBF 梯度或 QP 测量。

查询在单独进程中构建两棵树，使用同样的 1024 个均匀查询点、既有递归求值器，
预热后 7 批，每批 5 轮，报告每次查询的中位数。严格查询计时包含零值守卫逻辑。
原始/简化树标量求值和边界点守卫压力测试另有分项。

## 模拟相机输入

1655 点，341 个占据体素；782 个暴露单位面合并为 318 个 patch。
34 个无向支撑平面，原始边界有 58 种有向平面；实际树复用 66 个有向叶子定义。
压缩后的 X/Y/Z 间隔数为 10/8/13，总共 1040 个开单元；250 次事件格更新。
119 个 slab-local 自由棱柱，合并后 108 个，2 轮确认收敛。

| 指标 | volume rect | boundary X |
| --- | ---: | ---: |
| 有限区域数 | 150 个占据盒 | 108 个自由盒 |
| 平面引用 | 900 | 654（含外部 6 分支） |
| 唯一平面定义 | 62 | 66 |
| 树节点 | 1051 | 763 |
| 核心构建中位数 | 1.775 ms | 1.560 ms |
| 构建＋完整验证 | 89.526 ms | 143.993 ms |
| 严格非占据查询 | 5.670 μs | 3.815 μs |

树节点减少约 27.4%，但唯一平面字典略增。5 次核心时间样本：
rect 为 1.750–1.784 ms，boundary 为 1.527–1.640 ms。
这只是短时初步测量，不是硬实时或尾延迟保证。

均匀随机查询的零值守卫比例为 0，不代表实际控制轨迹不会触及边界；
额外边界点严格查询约 3.910 μs。完整验证探针中有 3081 次零值守卫。

## 必须保留的负结果

| 场景 | 原树节点 → 新树节点 | 原核心 ms → 新核心 ms | 原严格查询 μs → 新严格查询 μs |
| --- | ---: | ---: | ---: |
| 单体素 | 7 → 7 | 0.046 → 0.048 | 0.027 → 0.040 |
| 3×3×3 实心块 | 57 → 7 | 0.144 → 0.104 | 0.238 → 0.042 |
| U 表面 256 点 | 561 → 329 | 0.885 → 0.782 | 2.775 → 1.597 |
| 椭球表面 256 点 | 827 → 938 | 1.253 → 1.654 | 5.113 → 6.618 |
| 30 个分散占据体素 | 211 → 211（回退） | 0.391 → 0.477 | 1.144 → 1.049 |

分散输入触发压缩单元工作上限，未分配三维乘积大小的扫描空间，回退原 rect。
回退仍有边界提取/注册等前置开销；相同树的查询微小差异不应解释为算法收益。
椭球样例产生 133 个有限自由盒，比原 118 个占据盒更多。当前不会隐藏或自动舍弃这个负结果。
本轮没有实现按树大小自动选择 volume/boundary，也没有尝试三轴挑最好结果。

## 正确性与瓶颈

所有 12 个配置的构建/验证通过。原始点被判为自由的数量为 0；补充探针的误判自由和漏判自由均为 0。
完整整数证书检查来源、压缩单元均匀性、精确分区覆盖及树系数，不依赖随机探针通过来推断正确性。
新增 C++ 测试覆盖实心块、L/U、阶梯、薄壁、窄通道、闭腔、边/顶点接触、负坐标、随机体素簇，
穷举小例的面/边/顶点和内部接缝；Python 独立加载 manifest、树和占据参考验证分类及回退。
全部 13 项 CTest 通过；原默认输出与显式 `--tree-source volume` 的树/凸块导出逐字节一致。
新增核心测试还通过 AddressSanitizer + UndefinedBehaviorSanitizer；该容器运行时关闭 LeakSanitizer，未声称做了泄漏检查。
相机默认 rect 的简化树与旧 Phase 4 留存结果也逐字节一致。

相机核心热点仍是共享树构建/简化（约 0.8 ms），其次是占据索引及已有边界提取/合并；
二维分组和棱柱合并只占约 0.03/0.05 ms。
真正拖慢当前整次执行的是完整验证：约 140 ms 的补充探针反复计算新旧树、原始/简化树和占据 oracle。
整数覆盖证书本身约 1.6–1.9 ms。没有把这些费用算成零，也没有默认关闭验证。

结论：可以保留这个受控候选前端，但不能宣称整体运行已实现毫秒级。
本轮停在 X-sweep benchmark，不继续引入额外算法。
