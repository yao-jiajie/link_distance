# 连杆距离核心链路：分段计时与预编译 LSE 节点分派

## 范围

固定 Panda 球分解 URDF、`data/realistic_sparse_camera.xyz`、`h=0.02 m`、
`q=[0,-0.4,0,-2,0,1.6,0.8]`、环境位姿 `[0,0.3,0,0,0,0]`、
环境/连杆 LSE 标量误差预算各 `0.001 m`、margin `0.005 m`、4 workers。
`query_ms` 只覆盖运动学、环境 LSE 值与梯度、连杆归约；环境构建、验证、JSON 写入和
可视化不在内。使用 Release `-O3 -DNDEBUG`。

通过 `--profile-query true` 在查询内部取三段时间，28 次独立进程、前 3 次预热剔除，
其余 25 次的阶段中位数为：

| 阶段 | Median (ms) |
| --- | ---: |
| 运动学与球心整理 | 0.004792 |
| 环境 LSE 批量值与空间梯度 | 0.530947 |
| 球 clearance 与七组连杆 smooth-min | 0.003485 |
| 带分段时钟的完整查询 | 0.539618 |

阶段中位数分别计算，不能严格相加。环境场约占查询的 98%，因此只优化该段。
默认不启用 profiling，普通 `query_ms` 不支付分段时钟成本。

## 改动

构建 `SmoothTree` 时，节点类型和常见形状（叶、二元 MIN/MAX、三元 MAX）的子节点
索引预编译为顺序执行表。`link_distance_node` 为 trusted 批量路径开启此选项；
默认 checked API 和其他未显式启用的调用方保持旧分派。未重排子项、改变 LSE 公式、
减少梯度项或更改误差预算。其他元数仍走保持原顺序的通用分支。

复现实验：

```bash
cmake --build build -j4 --target link_distance_kernel_benchmark
build/link_distance_kernel_benchmark \
  resources/vamp/panda/panda_spherized.urdf \
  data/realistic_sparse_camera.xyz 0.02 0.3 301
```

同一进程从同一编译程序预构建两个平滑字段和各自工作区，旧分派与预编译分派逐轮交换顺序。每个模式测
301 次完整 `LinkDistanceEvaluator::evaluate()`，所有 59 个球的场值/空间梯度和
七组连杆值/关节梯度在计时外逐位比较。五次独立执行的各轮 Median/P95 的中位数：

| 模式 | Median (ms) | P95 (ms) |
| --- | ---: | ---: |
| 旧 trusted 分派 | 0.628966 | 0.705520 |
| 预编译分派 | 0.585256 | 0.661205 |

Median 降低约 6.95%，P95 降低约 6.28%。两种模式的结果逐位一致。单独进程
`query_ms` 对 CPU 频率及系统调度更敏感，尤其 P95；配对轮换测量更适合作为本次
小幅内核优化的验收。代码还对 unary、binary、ternary、宽元数和随机 DAG 的
trusted 值与全部梯度做逐位对照。

本次只减少执行分派与索引开销，不改变 `O(球数 × DAG 节点/边数)` 的渐近复杂度。
实验性地跳过零指数对应的梯度乘加虽在样例上通过，但不能普遍保证 signed-zero
位级一致，故没有纳入实现。

## 后续：球查询动态分块

59 个球的 LSE 计算成本随点位而变；固定连续分块在 6–8 worker 时会出现尾部等待。
新增每次领取两个球的动态分块，每个 worker 继续使用自己的缓冲区，输出仍写回原球序号。
节点默认 worker 数从 `min(4, hardware_concurrency)` 调为
`min(6, hardware_concurrency)`；显式设为 4 或更少仍使用原固定分块。

```bash
build/link_distance_kernel_benchmark \
  resources/vamp/panda/panda_spherized.urdf \
  data/realistic_sparse_camera.xyz 0.02 0.3 301 4 6
```

该命令在同一进程中轮换测量旧内核 4 worker、预解码内核固定分块 4 worker、
预解码内核动态分块 6 worker。五次独立执行，各自 301 次查询；表内数字是五次
Median/P95 的中位数，构建与逐位输出比较不计入时间：

| 方案 | Median (ms) | P95 (ms) |
| --- | ---: | ---: |
| 预解码、4 worker、固定分块 | 0.618717 | 0.747388 |
| 预解码、6 worker、动态分块 | 0.482630 | 0.696254 |

Median 下降约 21.99%，P95 下降约 6.84%；五轮的两项指标都下降。
所有球场值、空间梯度、clearance 和连杆距离/关节梯度逐位一致。
这项收益包含增加两个 worker 的并行度，不能归因于调度策略本身；在 4 worker
下动态分块略慢。更高 worker 数在本机能改善中位数，但 P95 波动较大，故保守
选择 6 作为默认上限。硬件并发度较低时默认值不会超过其报告值。

## 未采用：反向模式梯度原型

为检验单次查询能否降低梯度传播成本，试做了一个仅用于测量的反向模式原型：
前向逐节点计算 LSE 值，随后在 DAG 上反向累计权重与叶平面法向。
距离值逐位相同；本场景的球空间梯度及连杆关节梯度最大绝对差为
`3.33e-16`，但梯度不再保证逐位相同。五次独立进程、各 301 次交替测量的
Median/P95 中位数如下：

| 方案 | Median (ms) | P95 (ms) |
| --- | ---: | ---: |
| 当前预解码前向梯度、6 worker 动态分块 | 0.500380 | 0.634684 |
| 反向模式原型、6 worker 动态分块 | 0.593439 | 0.789940 |

该原型在本验收场景中更慢，故已撤回，不进入生产路径。机器的
`perf_event_paranoid=4` 阻止硬件计数器采样；因此目前只能确认端到端时间
变差，不能把原因精确归到内存写入、第二次 DAG 遍历或线程调度中的某一项。

## 后续：双球交错求值（已采用）

在每个 worker 内，将两个球的平滑场求值按 DAG 节点交错执行。两个球各有独立的
节点工作区，每个球内部的子节点访问、LSE 运算和梯度累加顺序不变。动态调度
每次领取两个球；奇数个球的末项仍走单球路径。额外工作区约为每 worker
`nodeCount × sizeof(ValueGradient)`，只在构建工作区时分配。

与当前 6 worker 动态分块但逐球遍历的路径相比，固定 Panda、相机点云、
`h=0.02 m`，五次独立进程、每次 301 次交替测量的 Median/P95 中位数：

| 方案 | Median (ms) | P95 (ms) |
| --- | ---: | ---: |
| 逐球遍历 | 0.494296 | 0.611292 |
| 双球按节点交错 | 0.456574 | 0.606638 |

Median 下降约 7.63%，P95 下降约 0.76%；五轮中两项指标均降低。
全部 59 个球的场值/空间梯度、clearance，以及七组连杆距离/关节梯度
逐位相同。单独的单元测试还覆盖奇数个点、不同 worker 数、静态与动态调度、
MIN/MAX、不同元数、随机 DAG 和极端坐标。复现仍使用上文的
`link_distance_kernel_benchmark ... 0.02 0.3 301 4 6` 命令，比较
`dynamic_*` 与 `paired_*` 字段。
