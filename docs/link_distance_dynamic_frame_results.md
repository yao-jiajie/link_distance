# 动态环境单帧距离计算

## 计时定义

机械臂 URDF 和球模型常驻，XYZ 文件读取在计时外。每个计时帧从内存中的新点云开始，
依次执行：稀疏体素占据、外露面提取与公共面合并、direct 半空间树构建、编译共享
DAG 与 LSE 场、创建该场的批量查询工作区，以及当前关节角下 59 个球和七组连杆的
距离/梯度计算。不包含证书验证、JSON、可视化和文件 I/O。

基准每帧都重新构建场，不使用上一帧的占据缓存。重复输入相同点数组只是为了稳定
控制场景复杂度；真实变化点云的耗时还会随占据拓扑变化。

## 六形状复杂点云结果

输入为 `data/panda_complex_scene.xyz`，9216 点，`h=0.02 m`，3989 个占据体素、
6869 个合并边界面、7286 个执行节点，Panda 固定配置
`[0,-0.4,0,-2,0,1.6,0.8]`，6 个查询 worker。每次执行包含一次预热加
11 个计时帧。初始基线为五次独立执行的中位数；优化后结果为十次独立执行，且与旧
CSE 路径正反顺序交替运行所得的中位数：

| 阶段 | 初始 Median (ms) | 优化后 Median (ms) |
| --- | ---: | ---: |
| 点云到稀疏体素 | 1.390 | 1.373 |
| 外露面提取与公共面合并 | 2.886 | 2.955 |
| direct 半空间树 | 6.234 | 6.839 |
| DAG、LSE 场与 evaluator 编译 | 3.230 | 0.509 |
| 批量工作区与线程 | 0.291 | 0.294 |
| 球/连杆距离和梯度查询 | 1.449 | 1.467 |
| **完整无验证帧** | **15.531** | **13.449** |

完整帧 P95 从 **16.286 ms** 降至 **14.414 ms**。优化后对应约 74.4 Hz 的
Median 帧率和 69.4 Hz 的 P95 帧率；相对初始基线，Median 改善 **13.4%**，P95
改善 **11.5%**。各阶段 Median 独立计算，不能要求它们精确相加。

```bash
cmake --build build -j4 --target link_distance_frame_benchmark
build/link_distance_frame_benchmark \
  resources/vamp/panda/panda_spherized.urdf \
  data/panda_complex_scene.xyz 0.02 11 intern
```

最后一个参数可用 `legacy` 运行“构建普通表达式、编译时 CSE”的对照路径，或用
`none` 关闭 CSE。关闭 CSE 会把执行节点从 7286 增加到 7652，并使查询和工作区
变慢，整帧没有收益。

为确认被测的未验证构建确实正确，基准在全部计时完成后对最后一帧执行完整证书验证；
它不计入帧时间，本机中位数约 1827 ms。生产系统若完全关闭验证，就不再拥有该帧的
严格符号证书；可考虑离线验证固定结构、降低验证频率，或把验证移到非实时线程。

## 已执行的核心链路优化

第一步让 direct 构建结果保存一次 postorder 序列化快照，后续编译不再重新遍历
`ExpressionPtr`。这一步把五次独立执行的完整帧 Median/P95 从
`15.531/16.286 ms` 降到 `13.772/15.154 ms`。

第二步在 direct 构建时用 `(operator, ordered child pointers)` 固定长度键精确
intern 子表达式，保持原有 Phi 折叠的构建身份语义不变。输出天然是 7286 节点的
共享 DAG，因此 `CompiledTree` 只做线性验证和指令生成，不再执行第二次 CSE 哈希
扫描。程序编译阶段由约 `1.0 ms` 进一步降至约 `0.225 ms`。构建期 intern 会给
direct 阶段增加约 `0.5--0.8 ms`，但十组新旧路径配对的帧时间差中位数仍约为
`-0.44 ms`，所以保留该实现。

数值等价性通过两层检查：直接树测试覆盖全部 255 个 `2x2x2` 非空占据模式及其他
形状，并逐点比较旧 CSE 与构建期 intern；复杂 Panda 场景的新旧 JSON 在排除两个
计时字段后逐字节一致，包括七个连杆 smooth 距离、关节梯度和 59 个球结果。

## 后续一轮：direct/边界构建优化

保持 `h=0.02 m` 和同一六形状点云，进一步作了五项不改几何语义的优化：

1. 把三维 prefix-box 求和固定为 8 项索引，并把每个轴上的候选切面体积分母移出内循环。
2. 边界提取时建立临时体素哈希集合，替代每个面的二分邻居查找；仍按原始已排序体素顺序生成面。
3. 为 2/3 子项表达式和序列化节点预留准确容量，消除小向量反复扩容。
4. direct Builder 在构造时同步发射整数 DAG，结束时仅对整数节点做可达压缩，保持与
   `serializeTree(ExpressionPtr)` 完全相同的 child-first 节点顺序。这样不再二次遍历
   `ExpressionPtr`；构造阶段的末尾序列化由约 `1.57 ms` 降为约 `0.26 ms`，其中
   包含整数 DAG 的可达压缩。
5. 展开 prefix 网格构造的连续内存索引与八项求和，减少每格重复索引计算。

以第 3 项后的二进制为本轮 A/B 基线，第 4、5 项完成后，六组正反顺序交替
运行、每组预热后 31 帧的配对结果：完整帧 Median 的组间中位数从 **13.51 ms**
降至 **12.52 ms**，配对差值中位数为 **-0.94 ms**，
direct-partition 阶段为 **-0.86 ms**；六组中分别有五组、六组更快。不同组的绝对
耗时随系统负载波动，配对差值比跨时段绝对数字更适合判断这轮收益。prefix 构造
单项在四组 101 帧 A/B 中约节省 `0.30 ms`；边界哈希在六组 11 帧 A/B 中将边界
提取从约 `1.5 ms` 降到约 `1.1 ms`，合并阶段输出顺序不变。

`boundary_direct_tree_test` 对 255 种非空 `2x2x2` 占据模式及其他形状逐节点比较
同步发射的 DAG 与原树遍历序列化，节点 ID、运算符、叶 ID、子项 ID 完全一致。
复杂 Panda 场景的新旧 JSON 除计时字段外逐字节一致，全量 `ctest` 为 **45/45**。

## 剩余优化空间

单独的子阶段剖析表明，direct-tree 的 registry 和 canonical occupancy 约为
`0.3 ms` 与 `0.5--0.9 ms`，prefix 构造约 `0.6--0.7 ms`，递归划分/表达式生成约
`3.3--3.8 ms`；一帧包含 34420 次 split 检查，表达式语义展开计数约 1860 万。
当前主要剩余方向为：

1. **固定或近似固定占据结构的跨帧复用。** 若新点仍落在相同体素集合，只需体素键
   计算/比较和约 `1.45 ms` 的查询，理论参考约 `3 ms/帧`。小范围体素变化可进一步
   尝试局部边界更新和受影响子树重建；全局移动导致坐标平面变化时仍需完整构建。
2. **优化 direct 划分。** 复用 prefix 子块计数、减少候选 cut 扫描，或直接发射紧凑
   指令而不创建中间 `ExpressionPtr`；这是当前最大阶段，但任何变换都必须保持有序
   min/max 与浮点运算顺序。
3. **优化边界合并。** 邻接已改为哈希查找；剩余主要是按朝向排序和矩形合并，约
   `1.2--1.5 ms`。任何替代索引需保证 patch 与 provenance 的确定性顺序。
4. **持久化线程池与容量型工作区。** 当前每个新场创建约 `0.29 ms` 的工作区和线程，
   可跨帧复用，但总收益上限不足 2%，不应先做。

只继续优化最后约 `1.5 ms` 的球距离查询，整帧收益仍受限；下一轮应优先考虑
direct 递归构建或跨帧增量环境更新。

## 初始帧专项优化（整数 DAG）

这一轮只优化新环境的首帧构建，不把证书验证、XYZ/URDF 读取、JSON 和可视化计入
核心时间。生产节点在 direct 构建时直接生成可执行的整数 DAG，不再同时创建
`ExpressionPtr` 图；严格验证或首个变化帧确实需要表达式时，才从已序列化 DAG
按需重建。通用 API 默认仍保留表达式图，只有距离节点显式选择整数模式。

同时完成了三项配套优化：

1. support/leaf 由有序映射改为按 registry ID 直接索引，并预留 partition、split 和
   leaf 状态容量。
2. canonical 体素定位在轴坐标跨度合理时使用小型稠密查表；跨度过大的非连通输入
   自动回退二分查找。四组 A/B 中 canonical 阶段均更快，减少
   `0.107--0.275 ms`。
3. 整数 DAG 的 `(operator, ordered child IDs)` 驻留使用项目内固定小键线性探测表，
   替代节点式 `std::unordered_map`。四组交替 A/B 中 direct 递归稳定减少
   `0.41--0.43 ms`，完整帧 Median 配对差值中位数约 `-0.287 ms`。

在相同 Panda、`data/panda_complex_scene.xyz`、`h=0.02 m`、101 个计时帧条件下，
改动前的现场基线为 Median/P95 `14.673/16.041 ms`；最终版三次独立执行的中间值为
`13.073/15.143 ms`，即 Median 减少约 `1.601 ms`（`10.9%`），P95 减少约
`0.899 ms`（`5.6%`）。最终版三次 Median 分别为 `14.045/12.525/13.073 ms`，
说明绝对耗时仍受系统负载影响；各子优化是否保留以正反顺序交替 A/B 为准。

```bash
build/link_distance_frame_benchmark \
  resources/vamp/panda/panda_spherized.urdf \
  data/panda_complex_scene.xyz 0.02 101 intern false
```

整数模式与表达式模式在 255 种 `2x2x2` 非空占据模式及其他形状上逐节点比较：
节点 ID、运算符、叶 ID、子节点 ID 完全相同，并通过按需表达式重建后的严格符号
认证。另有大坐标间隔用例覆盖稠密查表的有界内存回退。全量测试为 **48/48**。

## 初始帧专项优化（二）：边界与线程池

在上一节二进制基础上继续完成三项优化：

1. 边界外露面向量按最多六面精确预留；常见坐标范围内，把公共面合并所需的
   `(plane,v,u)` 排序键编码为单个 63 位以内无符号整数。若坐标跨度不能安全编码，
   自动使用原三字段排序。单项四组 A/B 中 merge 阶段全部减少
   `0.28--0.35 ms`。
2. boundary-plane registry 对小跨度坐标使用直接索引，并先统计每个 support 的
   provenance 数量再精确预留；任意 patch 顺序及极端 `int64` 坐标仍走有界内存
   回退。registry 阶段从约 `0.30--0.33 ms` 降到 `0.23--0.24 ms`。
3. 机械臂球数和 worker 数不依赖环境点云，因此节点在读取首帧前创建共享 batch
   executor。新场只建立与 DAG 节点数匹配的数值缓冲，不再启动/销毁 worker 线程。
   workspace 阶段四组全部减少，从 `0.37--0.49 ms` 降到 `0.27--0.30 ms`。

最终版与本轮开始前的保存二进制正反顺序交替运行四组、每组 51 个计时帧。完整帧
Median 四组全部更快，配对差值为 `-1.685/-2.006/-0.969/-0.398 ms`，差值中位数
约 **-1.327 ms**。边界、registry、workspace 三个目标子阶段的配对差值中位数分别
约为 **-0.514/-0.125/-0.175 ms**；其余差异来自同进程外系统负载和下游阶段波动。
四组最终版 Median 的跨组中位数约为 **11.70 ms**，只作为本次同机 A/B 参考。

batch executor 复用测试覆盖同一线程池连续绑定两个工作区且逐位结果不变；边界前端
原有的接近 `int64` 两端坐标用例覆盖打包排序和 registry 的回退路径。全量测试仍为
**48/48**。以上计时继续排除严格认证、文件 I/O、JSON 和可视化。

## 初始帧专项优化（三）：紧凑 prefix

direct partition 的三维积分表原来固定使用 64 位有符号元素。该表的值上界是 canonical
cell 数，因此在上界不超过 `uint32` 时改用 32 位无符号元素，超大输入仍使用 64 位
表；box sum 同时预计算两个 X/Y 基址，不再为八个角分别重复地址乘法。无符号加减按
模运算执行，但真实计数必须不超过 canonical cell 上界，否则仍立即报错。

四组正反顺序交替 A/B、每组 51 帧的结果：

- prefix 构建从 `1.14--1.22 ms` 降至 `0.63--0.65 ms`，配对差值中位数约
  **-0.551 ms**；
- direct 阶段四组全部更快，配对差值中位数约 **-0.964 ms**；
- 完整帧四组全部更快，配对差值中位数约 **-0.962 ms**。

另外试验了找到零混合切分后的 prefix-query 下界剪枝，但复杂场景只跳过
`488/34420` 次查询（`1.42%`），完整帧仅 2/4 组更快，已经回退。canonical 临时计数
表改为 32 位也只有 1/4 组子阶段更快，并使后续 prefix 代码布局回退，同样未保留。

最终版三次独立 101 帧的 Median 为 `12.144/11.241/11.263 ms`，中间值
**11.263 ms**；P95 中间值为 **13.409 ms**。相对最初的现场绝对参考
`14.673/16.041 ms`，当前 Median/P95 分别减少约 `3.410/2.632 ms`，但跨时段绝对值
会受系统负载影响，优化取舍仍以上述配对 A/B 为依据。全量测试保持 **48/48**。

## 初始帧专项优化（四）：体素排序、边界查找与分配

本轮继续保留四项局部优化：

1. 点到体素键在坐标总位宽不超过 63 位时编码为单个 `uint64_t` 后排序、去重并
   解码；任意大跨度输入回退到原三坐标排序。四组 A/B 的 occupancy 配对节省中位数
   约 **0.583 ms**，完整帧四组全部更快，配对节省中位数约 **0.873 ms**。
2. direct DAG 构造用栈上固定小数组暂存最多三个子节点 ID，只在确实产生新节点时
   分配最终 `children`。direct/递归/完整帧的配对节省中位数分别约
   **0.322/0.137/0.301 ms**；direct 四组中三组更快，第四组回退 `0.027 ms`。
3. 编译执行程序前精确统计并预留边数组。`program_compile` 四组全部更快，配对节省
   中位数约 **0.017 ms**；完整帧为 2/4 组更快，主要被其他阶段的系统波动淹没。
4. 边界 6 邻域查询在包围网格不超过 1600 万格且不超过占据数 64 倍时使用致密字节
   表，否则保持原哈希集合。当前场景包围网格约 23 万格，仅占约 224 KiB。四组 A/B
   中 boundary extract 从 `1.18--1.26 ms` 降至 `0.37--0.39 ms`，配对节省中位数约
   **0.824 ms**；整个 boundary 阶段节省约 **0.98 ms**，完整帧四组全部更快，配对
   节省中位数约 **1.84 ms**。

固定数组直接替换公共 `SerializedNode::children` 会同时波及通用编译、验证、写出和
测试接口，因此没有为数千个小向量分配进行高风险公共结构重写。prefix-query 下界
剪枝和 canonical 32 位临时计数等无稳定收益试验也继续保持回退状态。

最终版三次独立 101 帧的 Median 为 `11.427/10.512/10.237 ms`，中间值
**10.512 ms**；P95 中间值为 **11.685 ms**。相对上一轮绝对参考，Median/P95 分别
进一步减少约 `0.751/1.724 ms`。这些帧时间包含单帧点云体素化、边界、direct DAG、
场编译、工作区和一次七连杆距离/关节梯度查询，但不包含严格认证、文件 I/O、JSON
和可视化；单次严格认证约 `1.79--1.97 s`，在计时区外。全量测试为 **48/48**。

## 初始帧专项优化（五）：direct 构建

本轮针对 direct DAG 的 canonical、prefix 和递归子阶段继续优化：

1. 序列化 interner 将“查找，未命中后再次哈希并插入”合并为一次
   `find-or-create` 探测。四组 A/B 中 recursion 和 direct 均全部更快，配对节省
   中位数分别约 **0.128 ms** 和 **0.271 ms**；完整帧配对节省中位数约
   **0.423 ms**。
2. `BoundaryDirectOptions` 增加默认开启的 `retain_partition_diagnostics`。独立诊断
   管线保持原行为；距离节点和无验证核心基准关闭仅供诊断输出的 split 副本。recursion 为 3/4 组更快，配对节省中位数约
   **0.213 ms**；direct 总阶段配对节省中位数约 **0.038 ms**。
3. canonical 不再扫描整个压缩三维网格来寻找非零计数，而是在映射输入体素时记录
   首次命中的 cell，随后只检查这些 cell 的体积一致性。canonical 四组全部更快，
   配对节省中位数约 **0.248 ms**，direct 为 3/4 组更快。
4. prefix 从每格读取七个邻居的三维容斥公式改为连续的 Z、Y、X 三通道累计。
   prefix 四组全部更快，配对节省中位数约 **0.074 ms**。

试验过分区大对象原位构造和用引用参数包替换 `initializer_list<Term>`；两者都只有
2/4 组更快，目标 recursion 配对中位数分别回退约 `0.030 ms` 和 `0.037 ms`，因此
均已回退。

最终版三次独立 101 帧的 Median 为 `10.994/10.346/10.139 ms`，中间值
**10.346 ms**；P95 中间值为 **11.292 ms**。相对上一轮绝对参考
`10.512/11.685 ms`，Median/P95 分别进一步减少约 `0.166/0.393 ms`。最终三次
direct Median 为 `4.789/4.491/4.412 ms`，仍是初始帧最大的单项。计时继续包含一次
七连杆距离和关节梯度查询，并排除严格认证、文件 I/O、JSON 和可视化；全量测试为
**48/48**。

## 初始帧专项优化（六）：体素 bitset 与边界字节查找

紧凑坐标范围内，体素化阶段直接构建按字典序编码的致密 bitset，并从置位位置生成
有序唯一体素键，从而避免对原始点对应的重复三坐标键排序。大跨度或相对稀疏输入
继续回退到原 64 位打包排序或三坐标排序路径。

首次试验直接在边界六邻域查询中复用 bitset：occupancy 从约 `1.13 ms` 降到
`0.62 ms`，但逐位查询使 boundary extract 从约 `0.41 ms` 增到约 `0.64 ms`。
随后试验共享一字节/格的致密表，occupancy 和边界一致性扫描均回退，完整帧四组全部
变慢，因此未保留。

最终组合由 bitset 完成去重，边界阶段重新建立 cache-friendly 的一字节/格查找表。
相对直接复用 bitset 的四组交替 A/B：

- 完整帧四组全部更快，配对节省中位数约 **0.67 ms**。

## 初始帧专项优化（七）：字段工作区预热与跨环境重绑定

之前虽然字段线程池已在读取首帧前创建，但每棵新环境树仍会在核心计时内重新
分配每个 worker 的两组 `ValueGradient` 节点数组。现在由 `BatchExecutor` 在
环境到达前按节点上限预热缓冲区，环境树生成后只把逻辑长度重绑定到实际节点数；
环境变化时从旧 `LinkDistanceWorkspace` 回收同一批容量并交给新求值器。因此大
数组分配不再属于初始帧或变化环境帧的核心路径。

预热容量最多为 16384 节点，避免用户把 `max_direct_nodes` 设成很大的安全上限时
超大预分配；若实际树更大，重绑定仍会正常扩容，不改变功能和上限语义。距离、
空间梯度及关节梯度的计算算术没有改变。

在 `panda_complex_scene.xyz`、`--voxel-size 0.02` 上做四组旧/新交替 51 帧 A/B：

- 旧版 workspace Median 为 `0.645/0.605/0.534/0.561 ms`；
- 新版 workspace Median 为 `0.0069/0.0064/0.0077/0.0070 ms`；
- workspace 四组全部更快，配对节省中位数约 **0.576 ms**，降幅约 **98.8%**；
- 完整帧为 3/4 组更快，配对节省中位数约 **1.15 ms**，P95 配对节省中位数约
  **0.82 ms**。完整帧还包含其他阶段的频率和调度波动，因此可归因收益保守采用
  workspace 的约 `0.58 ms`。

最终版三次独立 101 帧 Median 为 `8.030/7.986/8.091 ms`，中间值
**8.030 ms**（约 124.5 Hz）；P95 为 `8.513/8.272/8.547 ms`，中间值
**8.513 ms**。计时包含环境构建和一次七连杆距离/关节梯度查询，排除严格认证、
文件 I/O、JSON 和可视化。新增测试确认重绑定前后距离值和关节梯度完全一致；
全量测试为 **48/48**。

## 初始帧专项优化（八）：序列化 interner 空槽位初始化

序列化 interner 继续保留原来的容量和负载因子，只把空槽位初始化缩减为写入
`value=-1` 占用标记；key 在槽位真正被占用时才从完整初始化的局部 key 复制。
查找过程先检查 `value`，因此不会读取空槽位中未初始化的 key，也不改变哈希、探测
顺序、节点编号或最终 DAG。

在相同场景上做四组旧/新交替 51 帧 A/B：

- prefix/interner 准备阶段四组全部更快，配对节省中位数约 **0.261 ms**；
- direct 总阶段为 3/4 组更快，配对节省中位数约 **0.274 ms**；
- 完整帧为 3/4 组更快，配对节省中位数约 **0.347 ms**。

本轮还试验了优先检查平衡切分、原位重排序列化节点、`small_vector` 子节点，以及按
占据量缩小 interner 容量。它们分别因收益过小、序列化变慢、编译/序列化变慢，或
哈希冲突增加导致递归变慢而回退。

最终版三次独立 101 帧 Median 为 `7.685/7.812/7.853 ms`，中间值
**7.812 ms**（约 128.0 Hz）；P95 为 `8.090/8.135/8.109 ms`，中间值
**8.109 ms**。相对上一轮绝对参考，Median/P95 分别减少约 `0.218/0.404 ms`。
计时范围仍为单帧点云输入到一次七连杆距离和关节梯度输出，包含环境构建，不包含
严格认证、文件 I/O、JSON 和可视化；全量测试为 **48/48**。

## 初始帧专项优化（九）：跳过核心链路中的边界面物化

距离计算只需要每个轴上的边界平面坐标和法向符号，不需要合并后公共面的矩形范围及
patch provenance。无认证核心链路现在直接扫描占据体素的六邻域并构造精简平面注册
表，随后生成与完整边界路径相同的 canonical occupancy、叶节点及序列化 direct
DAG。完整边界仍在计时区外生成，供严格认证和可视化使用。

紧凑包围范围使用按轴连续的符号数组；跨度过大或过于稀疏时自动回退到有序稀疏表，
避免按坐标跨度分配超大内存。生产缓存若已经为认证生成了完整边界，则继续复用完整
边界建立 direct tree，不重复扫描占据体素。

在 `panda_complex_scene.xyz`、`--voxel-size 0.02` 上进行三组同机旧/新 101 帧
配对 A/B：

- 旧版 Median 为 `7.826/7.898/7.650 ms`；
- 新版 Median 为 `7.270/7.311/7.411 ms`；
- 每组分别节省 `0.556/0.587/0.239 ms`，配对节省中位数为 **0.556 ms**，约
  **7%**；
- P95 每组分别节省 `0.376/1.056/0.280 ms`，配对节省中位数为 **0.376 ms**。

新路径三次独立 101 帧 Median 为 `7.675/7.437/7.750 ms`，中间值
**7.675 ms**（约 130.3 Hz）；P95 中间值为 **8.417 ms**。P95 会受到系统调度
和频率状态影响，因此优化验收以同机配对结果为主。

等价性测试覆盖全部 255 个非空 `2x2x2` 占据模式、随机/空腔/阶梯形状以及大坐标

## 移除增量更新路径
